## 一、贯穿全程的方法

**同一个接口,N 份实现,然后测。**(来自 Cornell ECE 2400 的五份 PA)

判断力训练在**事后的对比报告**里,不在事前的猜谜里。所以每一阶段的形状固定:

```
1. 接口(trait)先定死,行为规格写全
2. 实现 N 份(std 基线 + 你自己写的)
3. 全部拿 NaiveBook 对答案 —— 必须逐笔一致
4. 同一套 eval 口径测,填加速比
5. 写报告:理论 big-O 与实测是否吻合
6. 写 ADR:选了哪个、代价是什么、何时该推翻
```

`NaiveBook`(阶段 1 已完成)是这套方法的支点:它慢得离谱但**显然正确**,
是唯一能抓出「成交价错 1 个 tick」「排队顺序错一位」这类**语义**错误的手段。
不变量断言只能抓结构性错误。

三条硬规矩:

- **测试不过就拒绝评测**(`./scripts/eval.sh` 机械执行)
- **评测必须 release build**,debug 数字无意义
- **优化只许改实现,不许改接口** —— 为性能把私有字段改 `pub` 不可接受

### 第二部 · 数据结构与指针

**每个阶段一个部件,N 份实现,一份对比报告。这一部是老师点名的两块内容的主场。**

| 阶段 | 部件 | std 基线 | 你要实现的 | 逼出的指针知识 |
|---|---|---|---|---|
| **2** | 档位内队列 | `VecDeque` | ① `Box` 单向链表 ② 索引式**双向**链表 | `Box` / `Option::take` / 递归 `Drop` 爆栈 / **为什么 `Box` 写不出双向链表** |
| **3** | 价格档位索引 | `BTreeMap` | 数组化 ladder(price → 下标直接寻址) | 缓存局部性 / 有界离散域 / 内存换时间 |
| **4** | 订单索引 | `HashMap` | 开放寻址哈希表 | 探测序列 / 装载因子 / **删除的墓碑问题** |
| **5** | 订单存储 | `Vec<Order>` | 世代索引 arena | 悬垂引用检测 / ABA 问题 / `Rc<RefCell>` 的运行时 panic 代价 |

**阶段 2 是这一部的核心。** 撤单需要 O(1) 定位到订单在档位队列中的位置 ——
`VecDeque` 做不到(得先 O(n) 找)。这个需求把三种数据结构的差别逼到了台面上,
而「`Box` 能写单向链表但写不出双向链表」正是 Rust 所有权最经典的一课。

指针阶梯(每一步都有具体部件在等它,不是为学而学):

```
Box<T>  →  Option<Box<T>>  →  索引链接  →  Rc<RefCell<T>>  →  Weak<T>
   ↓             ↓                ↓              ↓              ↓
 阶段2a        阶段2b           阶段2c        阶段5(对比)    阶段5(打破循环)

  →  世代索引  →  NonNull + unsafe(可选)  →  自写 Drop/Deref  →  Arc<T>
        ↓                   ↓                        ↓              ↓
     阶段5              阶段5(延伸)              阶段7          阶段8
```

### 第三部 · 抽象与组装

**trait 从「两个阶段的话题」升级成「承重结构」** —— 第二部的每一对实现都藏在同一个 trait 后面。

| 阶段 | 内容 | trait 知识 |
|---|---|---|
| **6** | 泛型组装 `OrderBook<L: LevelQueue, I: OrderIndex>` + 快速撮合 | 多参数泛型 / `where` 子句 / trait 组合 / 扩展 trait |
| **7** | `dyn` vs 单态化的**实测**代价;运算符 trait / `Deref` / `Drop` / `From` | 虚表开销 / 对象安全 / 关联类型为什么破坏对象安全 |

关键设计:

```rust
trait LevelQueue {
    type Handle: Copy;                                   // ← 关联类型不是装饰
    fn push_back(&mut self, id: OrderId, qty: Qty) -> Self::Handle;
    fn remove(&mut self, h: Self::Handle) -> Option<(OrderId, Qty)>;
    // ...
}

impl LevelQueue for DequeLevel  { type Handle = OrderId; }  // remove 是 O(n)
impl LevelQueue for ArenaLevel  { type Handle = NodeRef; }  // remove 是 O(1)
```

**整个复杂度差异被编码在「Handle 能是什么」里。** 这就是关联类型存在的理由,
而不是一个语法特性。

### 第四部 · 并发内存通信

**核心保持单线程 —— 并发在它周围。** 这是真实交易所的架构,也是 HFT 并发技术的所在地。

```
   接入线程 ×N              撮合线程 ×1              发布线程 ×N
   解析 / 风控     ──环──►   单线程,不加锁    ──环──►   行情推送
                  (SPSC)                       (广播环,一写多读)
```

| 阶段 | 做什么 | 实测能看到什么 |
|---|---|---|
| **8** | `std::thread` + `Arc<Mutex<OrderBook>>`,多线程直接抢锁 | **锁竞争把吞吐打垮** —— 线程越多越慢。`Send`/`Sync`:为什么 `Rc` 过不了线程边界 |
| **9** | `mpsc::channel` + 单撮合线程 | 消息传递代替共享,吞吐回来了。背压与有界队列 |
| **10** | **自己写 SPSC 环形缓冲** | 原子索引 / `Acquire`-`Release` / `Relaxed` 会错在哪 / **伪共享** |

**阶段 10 的伪共享实验是这一部的宝藏**:生产者与消费者的索引落在同一 cache line 上时,
加一个 `#[repr(align(64))]` —— **一行改动,吞吐翻倍**。它就是 LMAX Disruptor 的核心洞察。

## 四、单次 session 的节奏(2–3 小时)

```
1. 读 stage-NN.md 的规格            20 min   接口和行为已写死,不需要猜
2. cargo test —— 看它红              5 min   先熟悉失败的形状
3. 实现,子步逐个跑绿             60-90 min
4. ./scripts/lint.sh                10 min   警告清零
5. ./scripts/eval.sh                10 min   拿到这一份实现的数字
6. 填报告的加速比那一行             10 min
7. git commit(一子步一个 commit)
```

阶段收尾时才写 ADR —— **两份实现都测完之后**,那时「代价」是测出来的数字,
不是想出来的形容词。
