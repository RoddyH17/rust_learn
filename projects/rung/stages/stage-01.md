## 4. 测试策略

### 三层测试

| 层 | 在哪 | 干什么 |
|---|---|---|
| **单元测试** | `src/*.rs` 里的 `#[cfg(test)] mod` | 和被测代码同文件,**能看见私有字段**。测「这段逻辑对不对」 |
| **集成测试** | `tests/public_api.rs` | 独立 crate,**只能碰 `pub`**。测「这个库好不好用」 |
| **doctest** | 文档注释里的 ```` ``` ```` 块 | 保证文档里的示例真的能跑 |

`src/types.rs` 里可以写 `Price(1005)`,`tests/public_api.rs` 里不行 ——
同一行代码在两个位置一个能编译一个不能,差别就是 day8 学的可见性。
`tests/public_api.rs` 里有两处**故意注释掉**的代码,取消注释能看到对应的编译错误。

### 定向测试的类别

已经给你的 71 个测试是按类别组织的。看一遍这张表,理解**为什么是这些类别**——
阶段 2 起你要自己设计测试,那时这张表就是模板。

| 类别 | 目的 | 例子 |
|---|---|---|
| 基本功能 | 正常路径能跑 | `挂单后序号从1开始递增` |
| 边界值 | 空、零、最大值 | `空簿子的各项查询`、`qty_加法溢出时返回空` |
| 非法输入 | 坏输入不崩溃 | `挂零量单被拒且簿子不变` |
| 状态不变 | **失败的操作不许留下痕迹** | `order_成交量超过剩余量时不改动任何东西` |
| 优先级 | 业务规则 | `价格优先_先吃便宜的卖单`、`时间优先_同价先挂的先成交` |
| 不变量 | 无论如何都成立 | `只用submit的簿子买一永远小于卖一`、`成交量守恒` |
| 确定性 | 同样输入同样输出 | `同一串操作跑两次结果完全相同` |

**「状态不变」这一类最容易被漏。** 一个操作失败时,它必须什么都没改 ——
半途而废的修改是最难查的 bug。

阶段 1 还不需要写随机测试,因为 `NaiveBook` **自己就是参考模型**,没有别的东西可对。

## 5. String 补课(欠了两天了)

day7 和 day7.5 各欠一次。现在还 —— 因为你马上要手写三个 `Display`。

### 5.1 `format!` vs `write!` —— 这是性能问题不是风格问题

```rust
// ❌ 多一次堆分配
write!(f, "{}", format!("{}.{:02}", a, b))

// ✅ 直接往 f 里写,零分配
write!(f, "{}.{:02}", a, b)
```

`format!` 在堆上分配一个新 `String`,把内容拷进去,再整个拷进 `f`,然后丢掉。
`write!` 直接往 `f` 这个缓冲区里写。

一次堆分配大约几十到上百纳秒。CLI 里一秒打几十行,无所谓;
撮合日志一秒几十万行,就是几十毫秒。

### 5.2 `push_str` vs `+` —— 所有权的差别

```rust
let mut s = String::from("10");
s.push_str(".05");     // s 还是 s,只是变长了
println!("{s}");       // ✅

let a = String::from("10");
let b = String::from(".05");
let c = a + &b;        // a 被移动进去了
// println!("{a}");    // ❌ E0382: borrow of moved value
println!("{b}");       // ✅ b 只是被借用
```

`+` 的签名是 `fn add(self, other: &str) -> String` —— 左边是 `self` 不是 `&self`。
它**拿走**左边的所有权,在原缓冲区上追加,再还给你。这样设计是为了少分配一次。

规律:**`+` 左边必须是 `String`(被移动),右边必须是 `&str`(被借用)。**

### 5.3 为什么 `String` 不能下标

```rust
let s = String::from("你好");
// s[0]                   // ❌ E0277:根本没实现 Index<usize>
println!("{}", s.len());  // 6,不是 2 —— 每个汉字占 3 字节
```

`String` 是 **UTF-8 字节序列**。一个字符占 1 到 4 字节:ASCII 1 个,汉字 3 个,emoji 4 个。

所以 `s[0]` 有歧义:第 0 个**字节**还是第 0 个**字符**?

- 字节:`s.as_bytes()[0]` → `228`,一个没有意义的数
- 字符:`s.chars().nth(0)` → `'你'`,但这是 **O(n)**,必须从头数

Rust 干脆不提供下标,逼你说清要哪个。切片语法 `&s[0..3]` 倒是有,
但它按**字节**切,切到字符中间会**运行时 panic**:

```rust
let s = String::from("你好");
let ok = &s[0..3];      // "你"  ✅ 正好在字符边界
// let bad = &s[0..1];  // 💥 panic: byte index 1 is not a char boundary
```

接上 day4 的切片:`&str` 是「一段 UTF-8 字节的视图」,而**视图边界必须落在字符边界上**。

| 你要写的 | 用哪条 |


这个脚本**先跑测试,不过就拒绝评测**。理由:评估一个不正确的程序的速度是没有意义的 ——
测出来的「快」只说明它错得很快。

它还强制用 `--release` 编译。debug build 关掉了全部优化、开着溢出检查和额外边界检查,
**用 debug build 测出来的数字和真实性能没有关系**。

### 三种订单流模式

只看规模会漏掉最重要的东西 —— 同一个订单簿在不同负载下可能差一个数量级。

| 模式 | 模拟什么 | 压哪条路径 |
|---|---|---|
| `insert-only` | 开盘前集合竞价堆单 | 挂单 + 最优价查询 |
| `high-cross` | 盘中活跃成交 | 撮合主循环 |
| `cancel-heavy` | 做市商高频改价 | 撤单定位 |

订单流用固定种子生成,所以**每次跑得到完全相同的一串** —— 数字可复现。

**ADR 在两份实现都测完之后写,不是开工前写。** 阶段 1 只有一份实现,

### `decisions/ADR-001-价格用定点整数.md`

候选至少四个:`f64` / 裸 `i64` / `Price(i64)` newtype / 十进制定点库(如 `rust_decimal`)。

最后一个别漏 —— 它是真实项目里的常见选择,你要能说出为什么这个项目不用它
(提示:看 `crates/rung-core/Cargo.toml` 里那条架构断言)。

「何时推翻」那一段写具体:`TICKS_PER_UNIT` 是编译期常量,意味着假设所有品种
tick size 相同。**什么场景会让这个假设崩?给一个具体的,不要写「以后可能」。**

### `decisions/ADR-002-封装与可见性.md`

记录三条决定及其代价:

1. `Price` / `Qty` 的字段私有,只能走 `from_ticks` / `new`
2. `Order` 的字段私有,改动收敛到两个 `pub(crate)` 方法
3. 模块私有 + `pub use` 重导出,而不是 `pub mod`

第 2 条最重要。写下这句话并想清楚它:

> **优化只许改实现,不许改接口。为了性能把私有字段改成 `pub` 是不可接受的 ——
> 那会破坏封装,也就改变了接口。**

这条规则后面九个阶段都成立。阶段 8 你会很想为了几个纳秒破坏它。
